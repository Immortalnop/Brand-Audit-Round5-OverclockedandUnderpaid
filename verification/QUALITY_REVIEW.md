# Quality and release review

The runtime preserves Aarush's acquisition, transport, composition, scoring and
five-skill structure. Selected Adya observations/value rules were corrected and
adapted. The complete required defect mapping is in DEFECT_DISPOSITIONS.md.
No Adobe SDK, website modification, dashboard or measured business uplift is claimed.

| Requested dimension | Retained evidence | Limit |
| --- | --- | --- |
| Safety/security | Input/packet bounds, atomic rejection, URL/redirect/DNS/TLS/robots tests, real interrupt and deadlines | Host tools remain governed by their host; declarations are not receipts |
| All-finding precision | Review CSV plus acquired observations/reports/packets | Human labels pending; defect precision and opportunity usefulness are separate |
| High-severity precision | Final six-site batch emitted no high/critical findings | No positive denominator and no independently reviewed false-high rate |
| Recall | Before/after traps and genuine positive controls, expected fixture check set | Fixture detection includes opportunities; it is not broad unseen-site recall |
| Calibration | Existing heuristic provenance preserved, scorer and dataset hashes frozen | Confidence is not a calibrated probability; independent ECE unavailable |
| Robustness | Blocked/no-evidence runs retained; failed About, missing optional tools, SPA and budget controls | Static sample cannot establish rendered-site absence |
| Evidence/actionability | Acquired quotations, supported reach, repairs, suggested roles and actual priority reasons | Role suggestions are not teammate assignments; usefulness needs review |
| Honesty | Per-check outcomes, unavailable denominators, late rehearsals retained, measured/enforced scope | Search and vision were explicitly unassessed in host rehearsals |
| Speed | Inclusive host workflow timestamps and request ledger/traces | Small local-host rehearsal set, not general p95 performance |
| Skill design | Five valid skill folders, one entrypoint, actual host packet read/outcome/merge/render | Metadata alone is not execution; optional tools were not exercised |
| Test effectiveness | Baseline probes and positive/trap production controls; complete and extracted suites | Passing tests establish those cases, not universal correctness |
| Maintainability | Small shared boundary/packet/semantic/value helpers, stable IDs and existing renderer/merger | Limited JSON-LD support is explicit; no remote context fetching |

Human review must inspect support, affected scope, status, severity and action
applicability for every row. Use tp, fp or irrelevant for label; fill reviewer and
human_reviewed only for actual person review. Keep every blocked/failed site in
runs.json. Do not tune on a set and continue calling it untouched holdout evidence.
No independent precision/ECE/business claims may be presented before review.

The final batch contains 64 findings (11 defects and 53 opportunities), eight
medium and 56 low. Five of six sites completed; one insufficient-evidence site
remains in completion accounting. Each finding has a separate agent triage note
in review-set/agent-triage.csv; human fields in findings-review.csv remain blank.
Intentional indexing exclusions, address ownership, parser-only accessibility
observations and generic commercial advice need particular attention. Agent
triage is not an independent correctness label. The previous batch that prompted
the profile repair is retained as development data.

A complete screen/presentation recording from the frozen candidate and confirmation
of the intended laptop are unverified. The recorded command/observation transcripts
are execution evidence, not a claimed video. Presentation limits (eight-minute
target, ten-minute stop, seven presented slides, five-minute Q&A) are separate from
the audit workflow's 270-second target and maximum 55-second host allowance.
